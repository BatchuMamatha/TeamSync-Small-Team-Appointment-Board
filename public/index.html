How TeamSync Works & Assumptions

Designed & Developed by Batchu Mamatha

⚡ Core Workflow & Key Features

  • Board & Timeline Views: Toggle between an intuitive 3-lane Kanban board (Scheduled, Completed, Cancelled) and a chronological list/timeline grouped by day.
  • Filtering & Realtime Search: Filter instantaneously by status, quick date chips ("Today", "Tomorrow", "All Dates"), or pick any custom date. Instant search filters across title, description, team member, and client.
  • Full Appointment Lifecycle: Create, edit, mark as completed, cancel, or reopen appointments with immediate visual status badges.
  • Visual Feedback & State: Clear toast notifications confirm every action, and validation banners explain exactly what went wrong when an input is invalid.

🛡️ Double-Booking & Conflict Detection Engine

The system strictly guards against two appointments occupying the same time slot on the same date.

Overlap Rule: (new_start < existing_end) && (new_end > existing_start)
  • Adjacent Slots Allowed: An appointment ending at 10:00 and another starting at 10:00 are non-overlapping and permitted.
  • Cancelled Slots Freed Up: When an appointment is cancelled, it remains visible for auditing/history, but its slot is freed so teammates can book it immediately.
  • Safe Updates: When editing an appointment, its own slot is excluded from conflict checking, allowing updates to description or title without false alarms.
  • Descriptive Conflicts: If a collision occurs, the system informs the user of the conflicting meeting's name and exact time range.

💡 Key Assumptions Made

  1. Shared Small Team Calendar: The board serves a small, tightly coordinated team where time slots represent shared conference/client capacity, so any conflicting booking on that date is prevented.
  2. Cancelled Retained: Cancelled appointments stay on the board in the "Cancelled" lane with distinctive styling to maintain an audit trail rather than being deleted silently.
  3. Instant Pre-seeded Data: Pre-populated with realistic sample appointments (today, tomorrow, upcoming) representing different statuses to facilitate immediate review.
  4. Storage Persistence: Data is persisted in server/data/appointments.json, surviving server restarts and test runs. A Reset Samples button is provided to restore the initial test state anytime.
